# Робот зачисления для МЭИ и СТАНКИН — дизайн

Дата: 2026-07-31

## Контекст

Робот зачисления (`src/robot/simulator.py`) уже умеет каскадно просчитывать выбывание
абитуриентов по приоритетам, но для этого ему нужен «полный пул» вуза — списки
абитуриентов ПО ВСЕМ направлениям (не только отслеживаемым), сшитые по уникальному
коду поступающего, чтобы понимать, куда освобождается место, если конкурент
поступает выше по своему приоритету.

Полный пул сейчас реализован только для двух вузов из пяти:
- `src/robot/mirea_pool.py` (МИРЭА, единый API `competitions_api`)
- `src/robot/fa_pool.py` (Финуниверситет, `listabit.php` + каталог `get_dict`)

Для МЭИ и СТАНКИН регистрации в `_POOL_FETCHERS` (`src/robot/universities.py`) нет,
хотя точечные парсеры баллов по отслеживаемым направлениям (`MpeiParser`,
`StankinParser`) уже работают и используются обычным дашбордом/CLI-обновлением —
их трогать не нужно.

`config/robot.json` уже содержит `dima_priorities` для МЭИ и СТАНКИН, но не
`dima_list_code` — без него `_resolve_dima_person` строит синтетического
участника вместо реального (с реальными баллом/согласием из пула).

## Цель

Реализовать `mpei_pool.py` и `stankin_pool.py` по образцу `mirea_pool.py`/`fa_pool.py`,
зарегистрировать их в `_POOL_FETCHERS`, добавить `dima_list_code` в конфиг — чтобы
команды `/робот МЭИ`, `/робот СТАНКИН`, `/робот обновить МЭИ`, `/робот обновить СТАНКИН`
(уже существующие в `scripts/telegram_bot.py`) заработали end-to-end без изменений
в самом боте, симуляторе или редакторе приоритетов.

## Область изменений

- Новый файл `src/robot/mpei_pool.py`
- Новый файл `src/robot/stankin_pool.py`
- `src/robot/universities.py` — регистрация двух функций в `_POOL_FETCHERS`
- `config/robot.json` — добавить `dima_list_code` для `"МЭИ"` и `"СТАНКИН"`
  (то же значение, что уже используется для `"МИРЭА"`, по подтверждению пользователя)

Симулятор, Telegram-бот, редактор приоритетов, дашборд, точечные парсеры —
без изменений: они уже написаны обобщённо через `SUPPORTED_UNIVERSITIES` /
`_POOL_FETCHERS` и подхватят новые вузы автоматически.

## Архитектура (общая для обоих модулей)

Точная копия механики `mirea_pool.py`/`fa_pool.py`:

- Класс `XxxFullPool` с методом `build(*, use_cache: bool = True) ->
  tuple[list[RobotPerson], list[RobotProgram], str, bool]`.
- Дисковый кэш `data/cache/{mpei,stankin}_robot_pool.json`, TTL 7200 сек,
  маркер `pool_scope: "full"` + `MIN_CATALOG_PROGRAMS`-guard на длину каталога.
- При ошибке сети — fallback на протухший кэш (`ignore_ttl=True`), если он есть;
  иначе исключение пробрасывается наверх (симулятор уже ловит и показывает
  пользователю как `error`).
- Свободные функции `fetch_mpei_full_pool(*, use_cache=True)` /
  `fetch_stankin_full_pool(*, use_cache=True)` — регистрируются в `_POOL_FETCHERS`.

## МЭИ (`mpei_pool.py`)

**Каталог направлений.** `GET https://pk.mpei.ru/info/entrants_list`.
Обычный HTML (BeautifulSoup, без Playwright/JS). Внутри страницы — несколько
`<table class="form-grid thin-grid align-left">`, каждой предшествует текстовая
метка уровня/формы обучения («Бакалавриат очная форма обучения», «...
очно-заочная...», «Магистратура...» и т.д. — 9 секций подряд). Нужна только
первая секция — «Бакалавриат очная форма обучения» (сразу после блока
чекбоксов-фильтров, до метки «Бакалавриат очно-заочная форма обучения»).
Внутри неё брать только ссылки с **точным** классом
`class="competitive-group listFilterBudget"` (без суффиксов `listFilterTarget`,
`listFilterSpecial`, `listFilterSeparate`, `listFilterContract` — это целевая
квота/платные места, не общий конкурс). Проверено вживую: 39 таких ссылок,
среди них все 5 уже отслеживаемых направлений (id 7, 22, 23, 35, 45 из
`config/programs.json`) совпадают по `entrants_listNNN.html`.
Название конкурсной группы — текст предшествующей `<td>` в той же строке
таблицы (совпадает дословно с названием в КЦП-таблице, см. ниже).

Извлекать секцию нужно поиском по тексту метки, а не по фиксированным
byte-offset — структура страницы должна остаться устойчивой к правкам вёрстки.

**Список абитуриентов.** `GET https://pk.mpei.ru/info/entrants_listNNN.html`
для каждой найденной ссылки. Пагинации нет (вся таблица на одной странице,
проверено на нескольких реальных `entrants_listNNN.html`). Переиспользовать
логику существующего `MpeiParser`: `_expand_row_cells` (раскрытие `colspan` в
двухуровневой шапке) + `header_index` (поиск колонки по названию, а не по
фиксированному индексу — набор колонок отличается между списками: обычный
бюджет / целевая квота / зачисление). Дополнительно, помимо уже парсимых
«Сумма», «Согласие», «Приоритет», извлекать 0-ю колонку «Уникальный код
поступающего» — по ней сшиваются участники между направлениями.

**Бюджетные места (КЦП).** `GET https://pk.mpei.ru/info/speclist_simple.html`.
Таблица `class="kcp-table"`, секция «Очная форма обучения» (`<a name="o">`).
Каждая строка — направление внутри конкурсной группы (при многопрофильной
группе — несколько строк с `rowspan` на общие ячейки), колонка «Всего» (первая
из группы колонок «В рамках контрольных цифр приёма») — число бюджетных мест.
Название конкурсной группы в этой таблице совпадает дословно с названием в
каталоге `entrants_list` (проверено на 2 реальных примерах) — сопоставление по
точному совпадению текста, тем же приёмом, что `fa_pool.py` использует для
своих программ. Если для какой-то строки сопоставление не нашлось —
резервный дефолт (`DEFAULT_BUDGET_PLACES`, как в `fa_pool.py`), это
аварийный, а не основной путь.

## СТАНКИН (`stankin_pool.py`)

**Каталог направлений.** Список из 21 значения `PROPERTY_394`, извлекается из
`<select>` на `https://priem.stankin.ru/bakalavriatispetsialitet/ranked-lists/`
(парсинг `<option>` тегов). Захардкодить как fallback-константу тот список,
что проверен сегодня (на случай если `<select>` окажется недоступен/изменит
разметку), но по умолчанию — динамический парсинг.

**Список абитуриентов.** `GET https://priem.stankin.ru/gridspisokpostupayushchikh`
с теми же параметрами, что уже использует `StankinParser` (`PROPERTY_388`,
`PROPERTY_389`, `PROPERTY_584`, `LIST_TYPE=ranked`, `EDU_LEVEL=bs`,
`PROPERTY_418`, `COL_CITIZENSHIP`), варьируя `PROPERTY_394`. Переиспользовать
`parse_table_by_headers` из `parsers/utils.py` (уже знает нужные колонки:
«сумма баллов с ид», «согласие на зачисление», «приоритет»), дополнительно
извлекать колонку «Уникальный код».

**Пагинация — подтверждено вживую реальными запросами.** Список не выдаётся
целиком одним запросом (по умолчанию видно только первые ~50 строк), но
пагинация — обычная GET-ссылка, а не AJAX/Bitrix-сессия, как можно было
предположить по неудачным попыткам `PAGEN_1`/`SIZEN_1`. На странице внизу
грида есть `<a class="main-ui-pagination-arrow-next" href="...&<param>=page-N">`.
**Параметр (сегодня это `lists_list_elements_91`) нужно брать из самой ссылки,
а не хардкодить** — имя параметра, судя по всему, привязано к конкретному
инстансу грид-компонента на странице и не гарантированно стабильно. Алгоритм:
запросить страницу, распарсить строки, найти `<a class="...-next">`; если он
есть — перейти по нему и повторить; если отсутствует — это последняя страница.

**Бюджетные места (КЦП).** `GET https://priem.stankin.ru/bakalavriatispetsialitet/nap/<код>/`
(например `/nap/09.03.04/`) — на странице встречается текст вида «65 бюджетных
мест на 2026/27» (проверено вживую). Извлекать код направления как префикс
`PROPERTY_394` (например `09.03.04` из `09.03.04 Программная инженерия`).
Если у направления несколько профилей на одной странице кода (например
`09.03.01` и `09.03.01.01` могут делить один `nap`-код) и число не резолвится
однозначно на конкретный профиль — резервный дефолт (`DEFAULT_BUDGET_PLACES`),
как и у МЭИ; это ожидаемый неидеальный случай, не блокер.

## Конфигурация Димы

Добавить в `config/robot.json`:
```json
"МЭИ": { "enabled": true, "dima_list_code": "<то же значение, что у МИРЭА>", "dima_priorities": [...] },
"СТАНКИН": { "enabled": true, "dima_list_code": "<то же значение, что у МИРЭА>", "dima_priorities": [...] }
```
`dima_priorities` уже заданы, менять не нужно.

## Обработка ошибок

Такие же соглашения, что и в `mirea_pool.py`/`fa_pool.py`: retry с backoff на
5xx-статусах (`FETCH_RETRIES`, `RETRYABLE_STATUS`), таймауты как у соседних
парсеров того же вуза (`requests.get(..., timeout=60)` для МЭИ,
как у `MpeiParser`; для СТАНКИН — как у `StankinParser`), при полном отказе —
fallback на протухший кэш, при отсутствии кэша — исключение наверх (симулятор
и бот уже показывают его пользователю как текст ошибки).

## Проверка

Новых команд/кода в боте не требуется — существующие `/робот обновить МЭИ`,
`/робот обновить СТАНКИН`, `/робот МЭИ`, `/робот СТАНКИН` становятся рабочим
сквозным тестом сразу после регистрации фетчеров в `_POOL_FETCHERS`. План
реализации должен включать шаг ручной проверки через эти команды (или
эквивалентный CLI-вызов `run_robot_simulation`) на реальных живых данных,
без моков сети — таков сложившийся в проекте стиль (у `mirea_pool.py`/
`fa_pool.py` тоже нет unit-тестов, полагаются на реальный прогон).

## Известные ограничения (осознанные, не блокеры)

- МЭИ/СТАНКИН: сопоставление КЦП по точному совпадению текста названия может
  не сработать для единичных нетипичных строк (например если официальный
  сайт использует чуть другую пунктуацию между двумя своими же страницами) —
  в этом случае используется `DEFAULT_BUDGET_PLACES`, а не падение симуляции.
- СТАНКИН: имя пагинационного GET-параметра читается из ссылки на странице,
  а не хардкодится — минимизирует риск, но полностью не исключает, что вуз
  сменит компонент грида в будущем.
