# Починка парсера Финуниверситета (FA) — дизайн

Дата: 2026-08-01

Задача в беседах: `priem-monitor-ht3`.

## Контекст

`FaParser.fetch()` (`src/parsers/remaining.py`) стабильно возвращает
`ValueError("Список Финуниверситета пуст")` по всем 4 отслеживаемым
направлениям (id 13, 42, 54, 78 из `config/filters.json`). Причина —
сайт `fa.ru/spiski/listabit.php` обновил вёрстку таблицы (новый
Bootstrap-интерфейс), добавив колонки «Уникальный код поступающего» и
«Финансирование» перед прежними, из-за чего все жёстко зашитые в парсере
позиционные индексы ячеек сдвинулись на 1:

| Что искал парсер | Индекс тогда | Индекс сейчас | Реальное содержимое сейчас по старому индексу |
|---|---|---|---|
| направление (для фильтра по ключевым словам) | `cells[3]` | `cells[4]` | Факультет/филиал |
| приоритет | `cells[4]` | `cells[5]` | текст программы (не число) |
| **балл** | `cells[9]` | `cells[10]` | колонка «Без ВИ» → `"Нет"` |
| согласие | `cells[17]` | `cells[18]` | «Наличие заключенного договора об образовании» |

Ключевое: старый `cells[9]` теперь указывает на `"Нет"` вместо балла →
`to_float("Нет")` даёт `None` → `score = 0` → строка `if score <= 0:
continue` отфильтровывает вообще все записи. Отсюда пустой список на
каждом направлении — это не сетевой сбой, а рассинхрон индексов после
редизайна сайта. Подтверждено живым запросом к сайту с текущей вёрсткой.

Редирект с `itype_list=бкл` (302 → тот же URL без этого параметра),
замеченный при диагностике, не связан с багом: `requests` сам проходит
его прозрачно вместе с cookie, финальные данные приходят корректно.
Убираем параметр только чтобы не тратить лишний round-trip на каждой
странице пагинации.

Проект придерживается принципа: если реальные данные не удалось
получить — это должно быть видно как ошибка, а не подменяться
приблизительным/усреднённым значением (см. также `откат на кэш при
системном отказе` в `src/robot/mpei_pool.py`/`stankin_pool.py`,
коммит `66f4ba8`). Этот фикс следует тому же принципу.

## Цель

- Список Финуниверситета снова возвращает реальных абитуриентов по всем
  4 отслеживаемым направлениям.
- Парсер устойчив к следующей перестановке/добавлению колонок на сайте
  ФА — не полагается на позиционные индексы.
- При недоступности ожидаемой колонки — явная, диагностируемая ошибка
  (имя колонки), а не тихий пустой список.
- Одиночный сетевой сбой/таймаут одной страницы пагинации не должен
  сразу ронять весь список направления — сначала повторные попытки.

## Область изменений

Только `FaParser` в `src/parsers/remaining.py`. Другие парсеры, `utils.py`,
`service.py`, робот-пулы — не трогаем (аудит `DEFAULT_BUDGET_PLACES=30` в
пулах ФА/МЭИ/СТАНКИНа — отдельная задача `priem-monitor-q1d`, вне этого
фикса).

## Извлечение колонок по `data-label`

Каждая `<td>` в таблице ФА размечена атрибутом `data-label` с человекочитаемым
названием колонки (`data-label="Сумма конкурсных баллов"` и т.п.) —
подтверждено живым HTML. Вместо позиционных индексов строим на каждую
строку словарь `{data-label: текст}` и берём значения по названию:

- `"Конкурсная группа/образовательная программа"` → текст направления
  (для фильтра по ключевым словам и исключения «очно-заоч»/«dot»/«дот»,
  логика фильтрации не меняется, меняется только источник текста).
- `"Приоритет зачисления, указанный поступающим по данной конкурсной группе"` → приоритет.
- `"Сумма конкурсных баллов"` → балл.
- `"Наличие согласия на зачисление"` → согласие.

Строки без цифры в первой ячейке (служебные строки вроде
`mobile-controls-label-row` с текстом «Данные») по-прежнему пропускаются
тем же условием, что и сейчас (`cells[0].isdigit()`).

Если для строки с цифровым № отсутствует `data-label` с одним из
ожидаемых названий (сайт снова переименовал/убрал колонку) — бросить
`ValueError` с указанием, какая колонка не найдена, вместо того чтобы
тихо считать балл/согласие пустыми. Это долетает до существующего
`except Exception as exc: return ProgramResult(..., error=str(exc))` —
поведение снаружи (`error` в `ProgramResult`) не меняется, меняется
только диагностируемость причины.

## Ретраи на уровне запроса

Обернуть HTTP-запрос за одной страницей списка (`requests.get(...,
params=...)`) в тот же паттерн ретраев, что уже есть в
`src/robot/mpei_pool.py`/`src/robot/stankin_pool.py`:

```python
FETCH_RETRIES = 3
RETRYABLE_STATUS = {500, 502, 503, 504}

def _get(url, params):
    last_error = None
    for attempt in range(FETCH_RETRIES):
        try:
            response = requests.get(url, params=params, headers=..., timeout=60)
            response.raise_for_status()
            return response.text
        except requests.HTTPError as exc:
            last_error = exc
            status = exc.response.status_code if exc.response is not None else None
            if status in RETRYABLE_STATUS and attempt < FETCH_RETRIES - 1:
                continue
            break
        except requests.RequestException as exc:
            last_error = exc
            if attempt < FETCH_RETRIES - 1:
                continue
            break
    raise last_error or RuntimeError(f"Не удалось загрузить {url}")
```

Без задержки между попытками — так же, как в существующих `_get()` в
`mpei_pool.py`/`stankin_pool.py` (сохраняем тот же стиль). Если все
попытки исчерпаны — исключение долетает до `except Exception` в
`fetch()`, направление помечается ошибкой как и раньше, но уже после
честной попытки получить реальные данные, а не с первого же сбоя.

## Что не меняется

- Пагинация: условие остановки `page_rows == 0 or page * 20 >= total`,
  регулярка `total:\s*(\d+)` для общего количества.
- Фильтрация по ключевым словам направления и исключение
  «очно-заоч»/«dot»/«дот» — та же логика, только источник текста меняется
  на значение по `data-label`.
- Формат `Applicant`/`ProgramResult` на выходе.

## Проверка

Автотестов на парсеры в проекте нет — сверка вживую (как и везде в этом
репо). План: живой прогон всех 4 направлений ФА (например,
`python3 update.py` или точечный скрипт по id 13/42/54/78) — списки
больше не пустые, баллы и приоритеты выглядят правдоподобно (баллы в
разумном диапазоне ЕГЭ-подобных сумм, а не 0).

## Известные ограничения (осознанные, не блокеры)

- Ретраи покрывают только сетевые сбои/5xx одной страницы пагинации —
  если сайт ФА снова поменяет вёрстку/названия колонок, парсер упадёт с
  понятной ошибкой (что и требуется), но не починится сам.
- Аудит и починка `DEFAULT_BUDGET_PLACES=30` (фейковый дефолт вместо
  реального КЦП) в пулах ФА/МЭИ/СТАНКИНа — сознательно вынесены в
  отдельную задачу `priem-monitor-q1d`, не входят в этот фикс.
