# Реальность бюджетных мест в робот-пулах — дизайн

Дата: 2026-08-02

Задачи в beads: `priem-monitor-q1d` (убрать фейковый `DEFAULT_BUDGET_PLACES=30`)
+ `priem-monitor-v0j` (сверить места с реальными КЦП). Финальный e2e —
`priem-monitor-6em`.

## Контекст

Робот-симулятор зачисления (`src/robot/`) считает **общий конкурс на бюджет**:
Этап 1 — БВИ с согласием, Этап 2 — общий конкурс по баллам ЕГЭ. Число мест
на программе (`RobotProgram.budget_places`) задаёт, за сколько мест идёт эта
конкуренция.

Каждый из 4 отслеживаемых вузов берёт места из своего источника:

| Вуз | Живой официальный источник | Фоллбэк |
|---|---|---|
| МИРЭА | API `plan` (`competitions_api`) | config `budget_places` |
| МЭИ | HTML `kcp-table` (pk.mpei.ru) | config → `DEFAULT_BUDGET_PLACES=30` |
| СТАНКИН | nap-страницы (`_nap_budget_places`) | сумма config-квот профилей → `30` |
| ФА | нет живого (только config) | config + `FA_PLACES_OVERRIDES` → `30` |

Проблема: `DEFAULT_BUDGET_PLACES = 30` — выдуманная заглушка (в `fa_pool.py`,
`mpei_pool.py`, `stankin_pool.py`), подставляется вместо реального числа мест.
Плюс config-значения могли устареть/содержать ошибки относительно официальных
КЦП.

### Важный принцип (общий конкурс vs квоты)

Официальный КЦП вуза («за счёт средств федерального бюджета») **включает
квотные места**: особая квота, отдельная квота, целевая квота. Абитуриенты на
эти квоты идут по отдельным спискам и **не входят** в список общего конкурса,
который парсит робот (ФА-парсер, например, тянет список с
`type_conkurs="Общий конкурс"`). Поэтому для робота нужны **места общего
конкурса**:

```
budget_places (общий конкурс) = КЦП − особая квота − отдельная квота − целевая квота
```

БВИ-абитуриенты (победители олимпиад) — исключение: они **внутри** общего
конкурса (робот их учитывает Этапом 1), их из мест вычитать не нужно.

## Решения (согласовано с пользователем)

1. «Реальное» число мест = живой КЦП **или** config из `ВУЗы.xlsx`. Плейсхолдер
   на исключение = только выдуманное `30`. STANKIN-сумма config-квот для
   смёрженных пар — **оставляем** (это config-значения).
2. Гарантия «реальное число или нет данных» — только для **отслеживаемых**
   направлений (в `config/programs.json`). Непрофильные программы каскада — вне
   охвата, им каскаду нужно какое-то число.
3. Поведение при «нет данных» у отслеживаемого направления: пометить **только
   это направление** («места: нет данных», без ✅/❌), исключить из расчёта
   зачисления; остальной прогон по вузу продолжается.
4. ФА: основной источник — config (живой PDF-парсинг в проде не делаем).
   Официальный КЦП ФА публикуется только в PDF — используем его как **разовую
   сверку** для правки config, не как живой источник.
5. Места общего конкурса = КЦП − особая − отдельная − **целевая** (вычитаем все
   квоты, включая целевую).

## Наблюдение о фактическом срабатывании `30`

При правилах выше выдуманное `30` **не задевает ни одно отслеживаемое
направление сегодня**: у всех 4 вузов отслеживаемые направления доходят до
config-значения раньше, чем до `30`. `30` реально срабатывает только на
непрофильных untracked-программах каскада (вне охвата). Поэтому:

- Часть A (nullable + «нет данных») — **защитная**: для отслеживаемых
  направлений ветка `None` сегодня не срабатывает (у всех есть config). Это
  страховка на будущее — чтобы новое направление без config показывало «нет
  данных», а не тихую заглушку `30`.
- Часть B (правка config) — **практически ценная**: config для ФА содержал
  ошибки относительно официального КЦП.

## Часть A: убрать `30`, ввести «нет данных» (`q1d`)

**Модель.** `src/robot/models.py`: `RobotProgram.budget_places: int` →
`int | None`. `None` = «нет данных о местах».

**Пулы.** Для **отслеживаемых** направлений цепочка источников:
живой КЦП → config → (STANKIN: сумма config-квот для смёрженных пар — оставить)
→ иначе `None`. Убрать `DEFAULT_BUDGET_PLACES = 30` как фоллбэк для
отслеживаемых. Для **untracked**-программ каскада число по-прежнему нужно —
оставить явно задокументированную аппроксимацию (константа переименована/с
комментарием «аппроксимация для непрофильных программ каскада, вне охвата
гарантии реальных мест»), не удаляя её для untracked-ветки.

**Симулятор.** `src/robot/simulator.py`: программа с `budget_places is None`
не участвует в расчёте зачисления (не создаёт «мест» для заполнения), в снимке
приоритетов помечается как «нет данных», без ✅/❌. Остальной прогон по вузу
идёт как раньше. Арифметика `remaining` для untracked-программ не меняется (у
них всегда int).

**Вывод.** `src/robot/format.py`: в строке приоритета с `budget_places is None`
показывать «места: нет данных» вместо «осталось X/Y … ✅/❌».

## Часть B: правка мест до общего конкурса по всем 4 вузам (`v0j`)

Расширено (по требованию пользователя): проверить и привести к местам общего
конкурса **все 4 вуза**, т.к. пользователь идёт чистым ЕГЭ-конкурсом (без
БВИ/олимпиад/инвалидных/целевого). Места общего конкурса = КЦП − особая −
отдельная − целевая квота.

### МИРЭА — верно, правок нет
`mirea_pool.py:128` берёт `plan` конкурса с `compType == "общий конкурс"` —
квотные конкурсы (отдельные `compType`) уже исключены. Это чистые места общего
конкурса. Подтверждено кодом.

### МЭИ — правка логики пула + config
Живой источник (`mpei_pool.py::_kcp_from_page`) берёт колонку «Всего» из

### СТАНКИН — override реальными основными местами

`priem.stankin.ru/bakalavriatispetsialitet/training_programs/` (+ страницы

## Область изменений

- `src/robot/models.py` — `budget_places: int | None`.
- `src/robot/simulator.py` — обработка `None` (пропуск в расчёте, пометка в
  снимке).
- `src/robot/format.py` — отображение «места: нет данных».
- `src/robot/fa_pool.py`, `src/robot/mpei_pool.py`, `src/robot/stankin_pool.py`
  — убрать `30` из фоллбэка отслеживаемых, оставить аппроксимацию для untracked
  (Часть A).
- `src/robot/mpei_pool.py::_kcp_from_page` — возвращать основные места.
- `src/robot/stankin_pool.py` — `STANKIN_KCP_OVERRIDES` для отслеживаемых
  направлений.
- `config/programs.json` — ФА: id 54→87, id 78→62; МЭИ: id 7→13, id 22→36,
  id 23→23, id 35→38, id 45→130.

Не трогаем: `mirea_pool.py` (верно), парсеры конкурсных списков, дашборд/бот вне
робота. Config СТАНКИНа не трогаем (место группы задаётся override; смёрженные
пары не выражаются одним config-полем).

## Обработка ошибок

Как везде в проекте — без падений наружу. `None`-места не должны ронять прогон:
симулятор и форматтер обрабатывают `None` явной веткой, а не исключением.

## Проверка

Автотестов на робот-пулы нет — проверка вживую (как во всех планах репозитория):
прогон `/робот` по 4 вузам реальным кодом, сверка отображаемых мест с
официальными КЦП (для ФА: id 54 показывает 87, id 78 — 62). Полный e2e —
отдельная задача `priem-monitor-6em`.

## Известные ограничения (осознанные)

- Часть A (nullable/«нет данных») для отслеживаемых направлений сегодня не
  срабатывает (у всех есть config) — защита на будущее.
- Живой источник КЦП для ФА не добавляем: официальный КЦП только в PDF, а config
  признан достаточным источником; сверка с PDF — разовая.
- Непрофильные untracked-программы каскада сохраняют аппроксимацию мест (вне
  охвата гарантии реальных чисел) — каскад по ним остаётся приблизительным.
