# Робот Московского Политеха — дизайн

**Дата:** 2026-08-06
**Статус:** согласован, готов к планированию

## Цель

Пятый вуз в роботе-симуляторе, по той же модели, что и четыре готовых:
локальный каскад считает прогноз сам, рядом — независимый оракул с сайта,
и расхождение видно сразу, а не прячется.

Политех уже отслеживается старым парсером позиций
(`src/parsers/remaining.py::MospolytechParser`, 9 программ в
`config/programs.json`), но робота под него нет: нет пула, и вуз выключен
в `TRACKED_UNIVERSITIES`.

## Почему Политех был выключен и почему включается сейчас

В `src/tracked_universities.py` строка «Московский политех» закомментирована
с объяснением: сервер `mospolytech.ru` не досылает промежуточный
TLS-сертификат, и все профили валились с `SSLCertVerificationError` каждый
цикл обновления.

Диагноз верен и подтверждён заново:

```
$ openssl s_client -connect mospolytech.ru:443 -servername mospolytech.ru
Verify return code: 21 (unable to verify the first certificate)
```

Сервер отдаёт только листовой сертификат `CN=*.mospolytech.ru`. Его эмитент —
`GlobalSign GCC R3 DV TLS CA 2020`, промежуточный, которого в `certifi` нет.
Эмитент уже промежуточного — `GlobalSign Root CA - R3`, и вот он в `certifi`
есть. То есть цепочке не хватает ровно одного звена.

`curl` работает, потому что берёт недостающее звено из системного хранилища
macOS; Python с `certifi` — нет. Чинится добавлением этого одного сертификата
к бандлу. Проверку сертификатов НЕ отключаем: `verify=False` превратил бы
источник официальных чисел в канал, который может подменить кто угодно.

## Источник данных

Единственный источник, подтверждён пользователем:

```
https://mospolytech.ru/postupayushchim/priem-v-universitet/rating-abiturientov/
```

Публичного JSON API у Политеха нет — искали, нашлись только сама страница и
сторонние агрегаторы, которые её же и парсят. Но под страницей есть ручка,
которую она сама дёргает через XHR:

```
POST https://mospolytech.ru/postupayushchim/priem-v-universitet/rating-abiturientov/fio_list_curl.php
Content-Type: application/x-www-form-urlencoded

select1=000000066_01&specCode=<код>&eduForm=Очная&eduFin=Бюджетная основа&f=1
```

Отдаёт HTML-фрагмент, а не JSON. Но по свойствам он ближе к API МИРЭА, чем к
постраничному скрейпу СТАНКИНа:

- **один запрос = направление целиком, пагинации нет** (проверено: 4296 строк
  одним ответом);
- **~1 секунда** на направление, ~400 КБ по проводу с gzip;
- **обрезать нечего** — либо ответ пришёл целиком, либо запрос упал, поэтому
  детектор молчаливого обрыва (как `_looks_truncated` у СТАНКИНа) не нужен;
- структура жёсткая: 25 ячеек в строке абитуриента, 9 в шапке.

Параметры формы берутся со страницы: `select1` = кампус/уровень (нам нужен
`000000066_01` — «Москва (бакалавриат/специалитет)»), `specCode` — из атрибута
`spec_code` у `<option>` в `<select id="select2">`.

### Каталог

`<select id="select2">` содержит 193 опции по всем кампусам и уровням. После
фильтра по `value="000000066_01"` остаётся **65 направлений** — это и есть
охват робота: Москва, бакалавриат/специалитет, очная, бюджет.

Все 9 отслеживаемых `parser_meta.specCode` из `config/programs.json` в этом
каталоге присутствуют — переименований не было.

Тянем **все 65**, а не только 9 отслеживаемых, по той же причине, что и в
остальных вузах: конкурент занимает место там, где у него выше приоритет, и
без чужих направлений каскад отправит на приоритеты Димы людей, которые на
самом деле давно сидят в другом месте.

## Модель: наш каскад + оракул сайта

Та же двухсторонняя схема, что в остальных четырёх вузах.

### Вход каскада

- **Места** — «Остаток бюджетных мест на общий конкурс» из шапки,
  `seat_source="live"`. Никаких оверрайдов и никакого ручного досчёта квот.
- **Люди** — все строки всех 65 направлений, склеенные по уникальному коду;
  выбор = (направление, приоритет), балл = конкурсный балл.
- Вердикт сайта о людях на вход НЕ попадает.

### Оракул

`Высший проходной приоритет` (idx 16) — номер наивысшего приоритета, на который
человек реально проходит. Отсюда:

- **проходит сюда** = ВПП непустой **и** ВПП == Приоритет (idx 14);
- ВПП непустой, но != Приоритет — проходит на направление выше по своему списку;
- ВПП пустой — не проходит никуда.

`passing_cutoff` = минимальный конкурсный балл среди проходящих сюда;
`site_passing_count` = сколько их. Ровно как `_passing_cutoff`/`_passing_count`
у СТАНКИНа.

**Оракул подтверждён дважды и сошёлся идеально.** Число прошедших совпало с
остатком мест **у всех 9 из 9** направлений — 36/36, 46/46, 45/45, 59/59,
59/59, 27/27, 67/67, 55/55, 52/52. Независимо то же число подтверждает колонка
«Реальный рейтинг» (idx 1), заполненная ровно у прошедших: на 09.03.01.07
непустых 52 при остатке 52.

Оракул считается только среди согласных: ВПП непустой у 719 человек из 4296, и
**все 719 — с согласием**, ни одного без. Это та же семантика, что у остальных
вузов, где проходной балл берётся среди согласных.

### Ловушка круговизны — явный запрет

ВПП != Приоритет технически означает то же, что «Зачисляется в другой КГ» у
МЭИ или «Исключен (зачислен на другой конкурс)» у МИРЭА, где мы такие строки
помечаем `enrolls_elsewhere` и выводим из борьбы.

**Здесь так делать нельзя.** У МЭИ и МИРЭА это пометка вуза об исключении
человека из списка. У Политеха ВПП — результат живого каскада самого сайта.
Скормив его на вход, робот перестал бы считать и начал переписывать ответ
оракула: сверка выродилась бы в сравнение ответа сайта с самим собой.

Поэтому `enrolls_elsewhere` у Политеха **не выставляется никогда**, а ВПП
используется исключительно для `passing_cutoff` / `site_passing_count`.

### Чего у Политеха нет: переноса квот

`quota_shortfall = None`, `vacant_places = None`, второго (оптимистичного)
прогноза нет.

Причина, а не недосмотр: «Остаток на общий конкурс» считается как КЦП минус
**фактически зачисленные** по квотам, то есть недобор квот в этом числе уже
учтён. А ПЛАНОВОГО распределения квот сайт не публикует, поэтому дельту
«столько-то мест перешло из квот в общий конкурс» посчитать не из чего и
показывать нечего: второй прогноз совпал бы с основным.

Это тот же случай, что МИРЭА, где квотных конкурсов нет в выдаче API вовсе
(см. комментарий в `mirea_pool.py`), — и прямая противоположность МЭИ, где
квотные списки публикуются отдельно и недобор считается
(`mpei_pool.compute_quota_shortfall`).

Формально это единственное, чего у Политеха не будет из общей модели. Всё
остальное — каскад, оракул, сверка мест, сверка прогноза, ничьи — на месте.

### БВИ

Отдельной фазы БВИ нет: зачисленные без вступительных испытаний уже вычтены из
остатка колонкой «Зачисленных без вступительных испытаний», и в конкурсных
списках их нет. `is_bvi=False` у всех — как у МИРЭА в бюджетном общем конкурсе.

### Ничьи

Обрабатываются существующим общим механизмом: `DimaPrioritySnapshot.is_tie` и
статус `boundary` в `PlacementCheck`. Правила тай-брейка не реализуются —
решение зафиксировано ранее: при равенстве баллов просто сообщаем, что ситуация
спорная.

Отмечаем на будущее: Политех — единственный вуз, где ничью в принципе можно
разрешить, потому что он публикует баллы по каждому предмету (idx 4,5,6) и
преимущественное право (idx 22). В этой работе не используется.

## Приоритеты пользователя

Робот берёт приоритеты **из пула вживую** — так работает текущая модель:
пользователь присылает боту свой уникальный код, `build_robot_settings`
собирает настройки на лету, `_resolve_dima_person` находит человека в пуле, и
реальный поданный порядок приходит вместе со строками списков. Никакого
`dima_list_code` в `config/robot.json` для Политеха заводить не нужно.

## Архитектура

### Новый модуль `src/robot/polytech_pool.py`

По образцу `stankin_pool.py`, но проще — нет пагинации, нет второго источника
мест, нет оверрайдов.

Публичный контракт (как у остальных пулов):

```python
CACHE_TTL_SEC = 7200
def fetch_polytech_full_pool(*, use_cache: bool = True) -> tuple[list[RobotPerson], list[RobotProgram], str, bool]
def read_polytech_cached_pool() -> tuple[list[RobotPerson], list[RobotProgram], str, bool] | None
```

Внутри:

- `_ca_bundle()` — путь к бандлу certifi + промежуточный GlobalSign, собирается
  один раз и кэшируется;
- `fetch_catalog()` — `spec_code` из `<select id="select2">` по
  `value="000000066_01"`, с `FALLBACK_CATALOG` из 65 проверенных значений на
  случай смены вёрстки (как у СТАНКИНа);
- `fetch_direction(spec)` → `(header, rows)`;
- `_parse_header(rows)` — 9-ячеечная строка с кодом → места;
- `_parse_people(rows)` — 25-ячеечные строки;
- `_passing_cutoff(rows)` / `_passing_count(rows)`;
- `PolytechFullPool` с `build` / `_fetch_all` / `_load_cache` / `_save_cache`;
- `ThreadPoolExecutor(max_workers=6)`, `requests.Session` на поток для
  keep-alive;
- `MAX_FAILED_FRACTION = 0.5` — при массовом сбое падаем на устаревший кэш, а
  не перезаписываем пул почти пустым датасетом.

Кэш: `data/cache/polytech_robot_pool.json`, `POOL_SCOPE="full"`,
`MIN_CATALOG_PROGRAMS = 50` (при 65 реальных берём с запасом вниз).

### Сертификат

`config/certs/globalsign-gcc-r3-dv-tls-ca-2020.pem` — публичный промежуточный
сертификат GlobalSign, кладётся в репозиторий (не скачивается в рантайме, чтобы
сборка пула не зависела ещё от одного хоста).

```
subject: C=BE, O=GlobalSign nv-sa, CN=GlobalSign GCC R3 DV TLS CA 2020
issuer:  OU=GlobalSign Root CA - R3, O=GlobalSign, CN=GlobalSign
годен:   2020-07-28 .. 2029-03-18
sha256:  76:25:38:43:95:09:C4:11:C4:37:D3:C5:67:56:3E:13:78:67:12:81:FC:4A:14:64:AD:D0:31:87:08:43:67:6E
```

Источник — `http://secure.globalsign.com/cacert/gsgccr3dvtlsca2020.crt`, адрес
указан в самом листовом сертификате в поле Authority Information Access.

### Правки существующих файлов

- `src/tracked_universities.py` — вернуть «Московский политех», убрать
  комментарий про SSL, коротко записать, чем починено.
- `src/robot/universities.py` — четыре словаря: `SUPPORTED_UNIVERSITIES`
  (`"Московский политех": "mospolytech"`), `_POOL_FETCHERS`, `_CACHE_READERS`,
  `_CACHE_TTLS`, плюс `_EXPECTED_REFRESH_SEC["mospolytech"] = 20`. Инвариант
  `SUPPORTED_UNIVERSITIES == TRACKED_UNIVERSITIES` при этом сходится.
- `src/robot/verification.py` — добавить «Московский политех» в
  `PLACEMENT_VERIFIED_UNIVERSITIES` и в комментарий над ним.
- `config/programs.json` — `budget_places` девяти программ на места общего
  конкурса; название `id26`.
- `config/robot.json` — порядок 63/71.

`src/robot/direction_keys.py` уже знает `mospolytech` (ключ = `str(program.id)`)
— править не нужно.

`src/robot/seat_oracle.py` — Политех НЕ добавляется. Этот модуль сверяет
захардкоженный резерв с сайтом, а у Политеха резерва нет: места приходят живьём
и единственным числом, сверять его не с чем, кроме себя самого.

## Производительность

Замерено 2026-08-06:

- 9 направлений в 5 потоков — **3 секунды**;
- все 65 в 6 потоков — **13 секунд**.

`_EXPECTED_REFRESH_SEC = 20` берётся с запасом. Для сравнения: МИРЭА 3 c,
МЭИ 35 c, СТАНКИН 205 c, ФА 225 c. Политех — второй по скорости.

Троттлинга при 6 потоках не наблюдалось. Поднимать выше не пробуем: выигрыш
секундный, а риск получить бан на источнике реальный.

## Проверка

Автотестов на пулы в проекте нет — проверка живой сборкой, как для остальных
четырёх вузов:

1. `fetch_catalog()` даёт 65 направлений, все 9 `specCode` из конфига внутри.
2. Полная сборка: 65 программ, `seat_source="live"` у всех, места девяти
   отслеживаемых совпадают с таблицей выше.
3. `site_passing_count == budget_places` у всех девяти — главный инвариант
   Политеха, и сегодня он выполняется 9 из 9.
4. Каскад: код `1824102` находится, приоритеты из пула совпадают с таблицей
   приоритетов выше.
5. Сверка прогноза даёт `match` (или `boundary` при ничьей), не `mismatch`.
6. `scripts/check_seats.py` по Политеху отрабатывает без ошибок.
7. Повторный вызов читает кэш и в сеть не ходит.

## Что осознанно не делается

- Правила тай-брейка при равенстве баллов — решение зафиксировано ранее.
- Второй, оптимистичный прогноз — считать не из чего (см. выше).
- Магистратура, аспирантура, филиалы, очно-заочная, заочная, платное —
  вне охвата.
- Старый `MospolytechParser` в `src/parsers/remaining.py` не трогаем: он решает
  свою задачу (позиция в списке) и роботу не мешает.
